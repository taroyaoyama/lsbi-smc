# 機械学習の前提知識

このドキュメントは、MVAE（マルチモーダル変分オートエンコーダ）を理解するために必要な機械学習の概念を、**初学者でもわかる**ように説明する。

概念の流れは以下のとおり：

```
ニューラルネットワーク基礎（層・活性化関数・学習）
    ↓
変分オートエンコーダ（確率的潜在空間・ELBO）
    ↓
モデル強化テクニック（ResBlock・CNN・正規化・Dropout）
    ↓
マルチモーダル VAE（2種類のデータを同一潜在空間へ）
```

---

## 1. ニューラルネットワーク基礎

### 1.1 1層で何をしているか

ニューラルネットワークの1層で行われていることは非常にシンプル：

$$\mathbf{y} = f(W\mathbf{x} + \mathbf{b})$$

| 記号 | 名前 | 意味 |
|------|------|------|
| $\mathbf{x}$ | 入力 | 前の層から来たデータ |
| $W$ | 重み行列 | 「どの情報を重視するか」を決める係数 |
| $\mathbf{b}$ | バイアス | 全体を一定量だけ「底上げ」する定数 |
| $f$ | 活性化関数 | 非線形性を与えるもの（後述） |
| $\mathbf{y}$ | 出力 | 次の層へ渡すデータ |

**$W\mathbf{x} + \mathbf{b}$ の意味（線形変換）：**

これは「入力の重み付き平均を取り、バイアスを足す」操作。どんなに複雑に見えても、この部分は必ず「直線（線形）」の操作になる。

**なぜ活性化関数 $f$ が必要か：**

もし活性化関数がなければ、100層重ねても結局「1枚の巨大な線形変換」と同じになってしまう。活性化関数は層に「折れ曲がり（非線形性）」を与え、複雑なデータを表現できるようにする。

### 1.2 活性化関数

| 名前 | 式 | 使いどころ |
|------|-----|---------|
| ReLU | $\max(0, x)$ | 中間層の標準。計算が高速で勾配が消えにくい |
| LeakyReLU | $x$ if $x > 0$ else $0.2x$ | 負の入力にも微小な勾配を流す。ReLUの「死」を防ぐ |
| Softplus | $\log(1 + e^x)$ | 常に正の値を返し、滑らか。**分散 $\sigma^2$ の出力に使用** |

**ReLU の「死（Dying ReLU）」問題：**

ReLU は入力が負のとき勾配がゼロになる。学習の途中で一部のニューロンがずっと負の入力を受け続けると、勾配が流れなくなり永遠に更新されなくなる（「死んだニューロン」）。LeakyReLU は負の側にも $0.2x$ という小さな傾きを持たせることでこれを回避する。

**Softplus が分散の出力に使われる理由：**

分散 $\sigma^2$ は必ず**正**でなければならない（負の分散は存在しない）。Softplus は $x \to -\infty$ でも $0$ に近いが決して $0$ にはならないため、分散を出力する層の活性化関数として適している。`mvae.py` のデコーダ出力（`var` の計算）でこれが使われている。

### 1.3 学習の仕組み：損失関数と勾配降下法

**損失関数 $\mathcal{L}$：**

モデルの「間違いの大きさ」を一つの数値で表したもの。「予測値と正解の差」を様々な方法で定式化する。

**勾配降下法：**

損失を最小化するようにパラメータを更新する。暗闇の山の中で「足元の傾き（勾配 $\nabla_\theta \mathcal{L}$）」を手がかりに谷底（損失最小）を目指す：

$$\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}$$

- $\eta$（学習率）：1ステップでどれだけ動くか。大きすぎると最適解を通り過ぎ、小さすぎると収束が遅い

**Adam オプティマイザ：**

単純な勾配降下法の改良版。2つの工夫を組み合わせている：

- **慣性（Momentum）：** 前回までの勾配の向きを「勢い」として維持し、一気に坂を下る
- **適応的学習率（RMSProp）：** 頻繁に更新されるパラメータは慎重に、あまり更新されないパラメータは大胆に動かす

初期学習率 `lr=1e-3`（0.001）は「まず試すマジックナンバー」。大外れしにくい標準的な値。

## 2. 変分オートエンコーダ（VAE）

### 2.1 オートエンコーダ：データの圧縮器

オートエンコーダは高次元データ $x$ を低次元の**潜在変数 $z$** に圧縮し、また元に戻す：

```
x → [エンコーダ] → z → [デコーダ] → x̂（再構成）
```

用途は「データの本質だけを抽出する」ことや「ノイズ除去」など。

しかし**通常のオートエンコーダ**は、データを潜在空間上の**「点」**として配置するため問題がある：

```
潜在空間（通常のAE）：
  ・ z₁（猫）   ・ z₂（犬）   ・ z₃（車）
  （点が離れ離れ→間を補間しても意味のある出力が出ない）
```

点と点の間を補間して新しいデータを生成しようとしても、「何者でもない」ノイズになってしまう。

### 2.2 VAEの核心：確率的潜在空間

VAEは、データを潜在空間上の**「広がりを持った分布（正規分布）」**として配置する：

```
潜在空間（VAE）：
  [〜猫〜]   [〜犬〜]   [〜車〜]
  （分布が重なる→間を補間してもそれらしい出力が出る）
```

- **エンコーダ $q_\phi(z \mid x)$：** データ $x$ を見て「これは平均 $\mu$、分散 $\sigma^2$ のガウス分布っぽい」と答える
- **潜在変数 $z$：** その分布からランダムにサンプリングされた値
- **デコーダ $p_\eta(x \mid z)$：** $z$ から元のデータを再構成する

```
           [エンコーダ q_φ]              [デコーダ p_η]
x → 層 → (μ_φ(x), σ²_φ(x)) → z ~ N(μ,σ²) → 層 → (x̂_μ, x̂_σ²)
```

### 2.3 再パラメータ化トリック

VAEの学習における最大の壁：**「サンプリング（乱数を引く操作）は微分できない」**

通常の書き方 $z \sim \mathcal{N}(\mu, \sigma^2)$ でサンプリングすると、そこで計算グラフが途切れてしまい、エンコーダへの勾配（バックプロパゲーション）が流れない。

**解決策：乱数を外に追い出す**

$$z = \mu + \sigma \cdot \epsilon, \qquad \epsilon \sim \mathcal{N}(0, 1)$$

「乱数を引く作業（$\epsilon$）」をネットワークの外に移し、ネットワークが担当するのは $\mu$ と $\sigma$ の計算だけにする。これにより $\mu$ と $\sigma$ への勾配が流れ、エンコーダ全体を学習できる。

```python
# mvae.py
def reparameterization(mean, var, device):
    epsilon = torch.randn_like(mean)
    return mean + torch.sqrt(var) * epsilon  # z = μ + σ * ε
```

### 2.4 ELBO（証拠下界）と損失関数

VAEの学習目標は、観測データ $x$ の周辺対数尤度 $\log p(x)$ を最大化すること。しかし $\log p(x) = \log \int p(x \mid z)\, p(z)\, dz$ は $z$ についての積分を含み直接計算できない。

変分推論を使うと、以下の**下界（ELBO）**が得られる：

$$\log p(x) \geq \underbrace{\mathbb{E}_{q_\phi(z|x)}[\log p_\eta(x|z)]}_{\text{再構成項}} - \underbrace{D_{\text{KL}}(q_\phi(z|x) \| p(z))}_{\text{正則化項（KL項）}}$$

ELBOを最大化することが $\log p(x)$ の近似的な最大化になる。実装では符号を反転して **$-\text{ELBO}$ を最小化**する：

$$\mathcal{L}_{\text{VAE}} = \underbrace{-\mathbb{E}_{q_\phi(z|x)}[\log p_\eta(x|z)]}_{\text{再構成損失}} + \underbrace{D_{\text{KL}}(q_\phi(z|x) \| p(z))}_{\text{KL損失}}$$

**2つの力の「せめぎ合い」：**

| 項 | 役割 | 暴走するとどうなるか |
|----|------|------------------|
| **再構成損失** | 「元のデータを正確に復元せよ」 | 分散を極限まで小さくして、普通のAE（点の配置）に戻ろうとする |
| **KL損失** | 「潜在分布を標準正規分布 $\mathcal{N}(0,I)$ に近づけよ」 | 全データを原点付近にギュッと押し込めてしまい、違いが区別できなくなる |

この2つのバランスが取れたとき、潜在空間は「似たもの同士が近くにいて、かつ適度に重なりを持つ」扱いやすい状態になる。

## 3. 残差ブロック（Residual Block）

### 3.1 問題：層を深くすると学習が崩れる

ニューラルネットワークは層を深くするほど表現力が上がるが、同時に**勾配消失問題**が起きやすくなる。誤差を後ろの層から前の層へ伝えるとき（バックプロパゲーション）、値が層を通るたびに小さくなり、前の層に届く頃にはほぼゼロになってしまう。

### 3.2 解決策：スキップ接続（ショートカット）

残差ブロックは、通常の処理ルートとは別に「何もしないでそのまま次に渡すルート」を設ける：

$$\text{output} = f(x) + x$$

```
入力 x ──┬──→ [Conv → BN → ReLU → Conv → BN] → f(x) ──→ (+) → 出力
         │                                                  ↑
         └──────────────────────────────────────────────────┘
                           スキップ接続（x をそのまま渡す）
```

**発想の転換：**

「ゼロから新しいものを作れ（$y = f(x)$）」ではなく、「今の自分（$x$）に、あと何を足せば（$f(x)$）良くなるか？」を学習させる。この「足すべき差分」が**残差（Residual）**という名前の由来。

**なぜ勾配消失が防げるか：**

$\text{output} = f(x) + x$ を $x$ で微分すると：

$$\frac{d(\text{output})}{dx} = f'(x) + 1$$

常に「$+1$」の項が残る。$f(x)$ の経路で勾配が消えかかっても、スキップ接続の経路から勾配が**ダイレクト**に伝わる。これにより100層を超えるネットワークでも正常に学習できる。

```python
# mvae.py
def forward(self, x):
    out_x = self.model(x) + self.bypass(x)  # f(x) + x
    return out_x
```

`self.bypass(x)` は入出力のチャンネル数が異なる場合にサイズを合わせる軽い変換（1×1 畳み込み）を行う。

## 4. 畳み込みニューラルネットワーク（CNN）

### 4.1 畳み込み層（Conv2d）：スライドするフィルタ

畳み込み層は、**カーネル（フィルタ）**と呼ばれる小さな窓をデータの上でスライドさせながら、局所的なパターンを抽出する：

```
入力データ：[a b c d e f g h ...]
カーネル(幅3)：[k₁ k₂ k₃]

位置0: a*k₁ + b*k₂ + c*k₃
位置1:       b*k₁ + c*k₂ + d*k₃
位置2:             c*k₁ + d*k₂ + e*k₃
...
```

**2つの重要な性質：**

- **局所受容野：** 全体を一度に見るのではなく、狭い範囲（例：幅3）に集中して特徴を探す。「隣り合う周波数との関係性」のような局所パターンの検出が得意
- **重み共有：** 同じカーネルをデータ全体に使い回すため、パラメータ数を抑えつつ「どこにそのパターンがあっても見つける」ことができる

**FRF データへの適用：**

FRFデータには特定の周波数帯に「共振ピーク」などの重要な特徴が現れる。CNNはこのような局所的な特徴の検出が得意なため、全結合層（FC）のみの処理より物理的特徴をうまく学習できる。

### 4.2 プーリング層（AvgPool2d）：要約と凝縮

プーリングは情報の「解像度」を落とす：

```
[2 4 6 8]  →AvgPool(幅2)→  [3  7]
              (2+4)/2=3     (6+8)/2=7
```

- 計算量が減る
- データが少しズレたりノイズが混じっても結果が大きく変わらない「頑健さ」を持つ

### 4.3 アップサンプリング（Upsample）：デコーダ側での復元

低次元に圧縮された特徴を元の解像度に戻す「引き伸ばし」。VAEのデコーダで、潜在変数 $z$ から高次元データを再生成するために必須。

```
[3  7]  →Upsample(×2)→  [3 3 7 7]（または補間で滑らかに）
```

### 4.4 本実装の工夫：1次元データを Conv2d で扱う

FRFデータの形状：`(batch, channels, 1, 1024)`

本来の1次元時系列データには `Conv1d` を使うが、本コードでは**あえて `Conv2d`** を使っている。

```
形状: (batch, ch, height=1, width=1024)
カーネルサイズ: (1, 3)  ← 縦方向は1（動かない）、横方向は3
```

- **縦サイズを1に固定**することで、実質的に1次元の畳み込みと同等の処理
- **将来への拡張性：** データを2次元（例：スペクトログラムや複数センサー）に拡張したくなっても、コード構造を大きく変えずに対応できる

## 5. スペクトル正規化（Spectral Normalization）

### 5.1 問題：重みが「暴走」するとネットワークが不安定になる

深いネットワークでは、学習中に重みの値が極端に大きくなり、入力のわずかな変化が出力の爆発的な変化を引き起こすことがある（**勾配爆発**）。

これを数学的に表現するのが**リプシッツ条件**：

$$|f(x) - f(y)| \leq K |x - y|$$

「入力が $|x - y|$ だけ変化したとき、出力は最大でも $K$ 倍しか変化しない」という約束。$K$（リプシッツ定数）が大きいほど不安定になる。

### 5.2 仕組み：最大特異値で割る

各層の重み行列 $W$ について：

1. $W$ の**スペクトルノルム $\sigma(W)$**（= 最大特異値 = その行列がベクトルを最大何倍に伸ばすかの指標）を計算
2. 重みをその値で割って正規化：

$$W_{\text{norm}} = \frac{W}{\sigma(W)}$$

これにより各層の「伸ばす力」が最大1倍に制限される。各層が1倍以下なら、何層重ねてもデータが暴走しない。

**BatchNorm との違い：**

| 手法 | 対象 | 目的 |
|------|------|------|
| BatchNorm | **データ（中間出力）** | 学習の高速化・安定化 |
| SpectralNorm | **重み行列** | 関数の「激しさ」を制限（リプシッツ性の保証） |

**実装：** PyTorchの `spectral_norm` はべき乗法（Power Iteration）という近似アルゴリズムで最大特異値を高速計算するため、計算コストをほぼ増やさずに効果を得られる：

```python
from torch.nn.utils import spectral_norm
spectral_norm(self.conv1)  # この1行で重みが正規化される
```

## 6. バッチ正規化（Batch Normalization）

### 6.1 問題：各層への入力分布が学習中にズレていく

深いネットワークでは、学習が進むにつれて各層への入力データの平均・分散が変化し続ける（**内部共変量シフト**）。後ろの層は「前の層の出力が変わり続ける」という不安定な環境で学習しなければならない。

### 6.2 仕組み：ミニバッチ内で正規化してリセット

各層の出力を、**そのミニバッチ内での統計量**を使って標準化する：

$$\hat{x} = \frac{x - \mu_{\text{batch}}}{\sqrt{\sigma^2_{\text{batch}} + \epsilon}}$$

- $\mu_{\text{batch}}$：ミニバッチ内の平均
- $\sigma^2_{\text{batch}}$：ミニバッチ内の分散
- $\epsilon$：分母がゼロになるのを防ぐごく小さな値（例：`1e-5`）

この操作で $\hat{x}$ は平均0・分散1に揃えられる。

### 6.3 スケールとシフトの再学習

平均0・分散1に固定してしまうと、活性化関数（ReLU等）の表現力が損なわれる場合がある。そのため、学習可能なパラメータ $\gamma$（スケール）と $\beta$（シフト）で「元の分布に戻す自由度」を与える：

$$y = \gamma \hat{x} + \beta$$

$\gamma$ と $\beta$ はネットワークが「最適な分布のスケール・位置」を自分で学習する。

**3つのメリット：**

1. **学習の高速化：** データのスケールが揃うため、大きな学習率を使える
2. **初期値への依存度が下がる：** 重みの初期値が多少ズレても補正される
3. **わずかな正則化効果：** ミニバッチごとのノイズが過学習を少し抑える

### 6.4 学習時と推論時で挙動が変わる

- **学習時（`model.train()`）：** そのミニバッチの $\mu_{\text{batch}}, \sigma^2_{\text{batch}}$ を使う
- **推論時（`model.eval()`）：** 学習中に蓄積した**移動平均**の統計量を使う

> **注意：** `model.eval()` を忘れると、推論時にもミニバッチ統計を使ってしまい、バッチサイズや入力順序によって結果が変わる。

## 7. ドロップアウト（Dropout）

### 7.1 問題：過学習（丸暗記）

ニューラルネットワークは非常に強力なため、訓練データを完璧に「暗記」してしまうことがある。訓練データの損失は下がり続けるが、見たことのない**検証データの損失は上がっていく**状態が**過学習**。

### 7.2 仕組み：ランダムに「選手を休ませる」

訓練の各ステップで、確率 $p$ でランダムにニューロンを無効化（ゼロにする）：

```
通常の出力：[0.5, 0.8, 0.3, 0.6, 0.9]
ドロップアウト後：[0.5, 0.0, 0.3, 0.0, 0.9]  ← 一部がゼロに
```

- **毎回違う組み合わせ**のニューロンがオフになる → ネットワークは「誰がいなくても機能するチーム」を学習
- **特定ニューロン同士の共謀（共適応）を防ぐ**：「このニューロンがこうなったら、あのニューロンがこうなる」という過学習パターンを壊す
- アンサンブル学習（多数のネットワークの平均を取る）に近い効果が得られる

### 7.3 学習時と推論時で挙動が変わる

- **学習時（`model.train()`）：** ランダムにニューロンを無効化
- **推論時（`model.eval()`）：** ドロップアウトを**完全にオフ**にする

> **注意：** `model.eval()` を忘れると推論のたびに結果がランダムに変わり、精度が大幅に低下する。これは「PyTorchでテスト結果がおかしい」の原因第1位。

## 8. 早期停止（Early Stopping）

### 8.1 過学習をリアルタイムで検知する

エポック数（学習の反復回数）をあらかじめ決めていると、「300エポックで止める」といった判断が難しい。多すぎると過学習し、少なすぎると学習不足になる。

**損失の推移で見極める：**

```
損失
  ↑
  │  訓練損失      ↘
  │  検証損失   ↘     ← ここが最適！
  │             ↘ ↗  ← 検証損失が上がり始めた（過学習の開始）
  │
  └──────────────────────────────→ エポック
```

訓練損失は下がり続けるが、検証損失が上がり始めたら「これ以上の学習は有害」。

### 8.2 実装のロジック

```python
# train.py
if vl_loss < best_vl_loss:
    best_vl_loss = vl_loss      # 自己ベストを更新
    epochs_no_improve = 0       # カウンターをリセット
    torch.save(model, ...)      # この時点のモデルを保存 ← 最良モデル
else:
    epochs_no_improve += 1      # 更新できなかった回数をカウント

if epochs_no_improve >= patience:
    break                       # 我慢の限界 → 終了
```

| 変数 | 役割 |
|------|------|
| `best_vl_loss` | これまでの検証損失の最小値（自己ベスト） |
| `epochs_no_improve` | 自己ベストを更新できなかった連続エポック数 |
| `patience` | 「我慢強さ」。この回数まで更新なしでも続ける |

`patience` が短すぎると学習の一時的な停滞で「やめ」てしまう。長すぎると過学習後のモデルを使うことになる。一般的には 10〜30 程度から始める。

## 9. マルチモーダル VAE（MVAE）

### 9.1 「マルチモーダル」とは

人間は「リンゴ」を視覚（赤い・丸い）、触覚（ツルツル）、味覚（甘酸っぱい）という異なる情報源（モダリティ）で認識するが、頭の中では統合して「一つのリンゴ」として理解している。

本プロジェクトの2つのモダリティ：

| モダリティ | データ | 次元 |
|-----------|--------|------|
| $x$（FRF） | 建物の周波数応答関数 | 1024次元 |
| $\theta$（パラメータ） | 各階の剛性 $k_1, k_2, k_3, k_4$ | 4次元 |

### 9.2 共通の潜在空間 $z$ を作る意味

通常のVAEが「$x \leftrightarrow z$」という1対1の往復なのに対し、MVAEは**「$x \leftrightarrow z \leftrightarrow \theta$」**という三角関係を築く：

```
FRF データ (x)           構造パラメータ (θ)
     │                          │
     ↓ enc_x                   ↓ enc_w
  q(z|x) ─→ [共通の潜在空間 z] ←─ q(z|θ)
                   │
                   ↓ Decoder
              再構成 x̂
```

これにより「**翻訳**」が可能になる：

- **FRF → パラメータ：** 観測した振動データ $x$ を enc_x で $z$ に落とし、$z$ から剛性 $\theta$ を推定する（= 今回のベイズ推論の目標）
- **パラメータ → FRF：** 仮想の $\theta$ を enc_w で $z$ に落とし、$z$ から対応する FRF を生成する（= 尤度計算に使う）

### 9.3 潜在空間を「共有」させる学習の工夫

2つのエンコーダが**同じ空間** $z$ を使うよう強制するために、損失関数に**双方向 KL 項**を加える：

$$\mathcal{L}_{\text{MVAE}} = \underbrace{\mathcal{L}_{\text{recon}}}_{\text{再構成}} + \underbrace{D_{\text{KL}}(q(z|x) \| q(z|\theta))}_{\text{enc\_x ↔ enc\_w を揃える}} + \underbrace{D_{\text{KL}}(q(z|\theta) \| q(z|x))}_{\text{逆向きも揃える}}$$

- KL は非対称（`01_math_prerequisites.md` §4 参照）なので、両方向の項を足すことで「どちらの方向からでも一致するよう」学習させる
- これが通常の VAE の KL 項（潜在分布を $\mathcal{N}(0,I)$ に近づける）と異なるMVAE固有の設計

詳細は [04_mvae.md](04_mvae.md) を参照。

## まとめ：各技術の役割

```
MVAE モデル構造
├── エンコーダ enc_x（FRF → z）
│   ├── Conv2d（局所パターン抽出）
│   ├── ResBlock（深い層でも学習安定）
│   ├── SpectralNorm（重みの暴走防止）
│   └── BatchNorm（各層の入力を整流）
│
├── エンコーダ enc_w（θ → z）
│   ├── 全結合層 FC（低次元変換）
│   ├── ResBlock
│   └── Dropout（過学習防止）
│
└── デコーダ（z → FRF再構成）
    ├── FC層 + Upsample
    ├── ResBlock
    └── Softplus（分散 σ² を正に制限）

学習ループ
├── Adam（適応的学習率で効率的に最適化）
├── ELBO損失（再構成 + 双方向KL）
└── Early Stopping（過学習を検知して停止 → best モデルを保存）
```
